# 架构

英文版本：[ARCHITECTURE.md](ARCHITECTURE.md)。

## 数据流

`BaseAdapter` 将飞书 SDK 与 React 隔离。它加载当前选区、表格级字段元数据、当前视图的可见记录 ID，以及整个数据表的记录 ID 列表。它通过 `IFieldMeta.isPrimary` 识别唯一主字段，将其置于 Compare View 的首位，并使用其格式化值作为记录标题。字段元数据的位置绝不会用于推断主字段。适配器优先保留当前视图的记录顺序，再按已格式化的主字段标题排列其余候选记录。

`useCompareConfig` 提供两份类型化配置及待共享列宽补丁：

- **draft（草稿）**驱动选择器与本地筛选/分组/排序控制；
- **applied（已应用）**驱动矩阵，且只会在 `setData()` 成功后改变；
- 待共享列宽即时覆盖矩阵展示，自动共享时不提交草稿。

Bridge 载荷带有 schema 版本并限定到当前数据表与视图。它只包含插件设置：所选 ID、隐藏 ID、筛选条件、排序规则、分组字段、字段顺序、换行字段 ID 和列宽。`configAccess` 优先读取按数据表/视图隔离的显式 Bridge key，再回退到旧默认 key；只有可编辑的网页宿主才会迁移已读到的旧数据。共享数据读取、编辑能力检查与事件订阅会独立失败：权限或订阅 API 不受支持时只会将宿主降级为只读，不会隐藏已经成功加载的配置。`DataChange` 会重新加载共享配置；未保存的本地草稿会被保留，并提示远端发生变更。

`useFieldValues` 会按需加载查询控制所需的原始字段值。`queryEngine` 是纯函数：规范化值、筛选、稳定排序，并让一条记录最多进入一个分组。`deriveCandidateRecords` 只根据查询规则推导候选顺序，不依赖勾选顺序或对比列顺序。`useCellValues` 加载结构化矩阵值，其中包含稳定的显示文本以及仅存于内存的附件呈现元数据。`cellLoading` 每批生成最多 12 个单元格读取任务，完成一批即发布一批；单格失败降级为空值，不清空其他单元格。取消加载会停止后续批次并忽略旧结果，已发出的 SDK 请求可与新一轮加载短暂重叠。请求由字段和记录集合而非顺序标识，因此列重排不会重新读取。相同适配器内复用仍被选中单元格的值，新适配器清除旧数据源的值，被移除的单元格也从缓存清除。

配置仍使用版本 1 和原有分表/视图 Bridge key；所选 ID 保留校验及去重，不设数量上限，也不截断。

宿主主题和语言属于呈现状态。语言与折叠状态不会写入 Bridge 载荷。

## SDK 边界

已安装的 `@lark-opdev/block-bitable-api` 声明提供了适配器所用的以下操作：

- `bitable.base.getSelection()`、`getTableById()`、`getPermission()`，以及兼容回退 `isEditable()`；
- 表格与视图元数据、`getRecordIdList()` 和可见记录 ID；
- 字段 `getFieldValueList()`，以及原始单元格值回退；
- `getCellString()`、`getCellValue()` 格式化回退，以及用于图片附件的 `getCellThumbnailUrls()`；
- 表格/Base 变更监听器，以及 Bridge 主题和数据变更监听器；
- `bitable.bridge.getData()` 和唯一允许的可变操作 `bitable.bridge.setData()`。

移动端判断保留在 `BaseAdapter` 中。手机宿主与网页宿主读取相同的显式 Bridge key，跳过编辑能力调用，并向 React 返回只读原因。宿主不支持的事件注册会降级为空订阅，使初次渲染和手动刷新仍然可用。

没有 SDK 调用会写入 Base 的记录、单元格、字段或视图。如果宿主切换期间当前选区的视图暂时不可用，适配器会回退到该数据表的第一个可用视图，并在下一次选区变更时刷新。

## 呈现层

`QueryToolbar` 是唯一的工具条。它负责浮层定位、点击外部与 Escape 关闭，以及行高菜单；但其展开的面板由 `App` 控制，以便空状态能够打开记录浮层。`App` 以插槽方式传入记录面板和保存操作，使草稿与配置逻辑不进入工具条。

`RecordSelector` 渲染该记录面板：所有可选记录放在同一个列表中，并附带本地搜索框。复选框只改变选择状态，不改变候选位置；拖动排序仅在对比表头提供。

`CompareTable` 接收已保存的字段、已分组的已保存记录、结构化显示值以及存在差异的字段 ID 集合。它负责仅矩阵使用的可折叠分组控制、固定表头、固定字段列及各列独立调宽手柄、记录列的排序与移除、用于展示完整内容的字段整行展开，以及只读附件图库。`StatBar` 与 `TableSkeleton` 是纯展示组件。这些组件都不会重建飞书原生编辑器。

`compareDiff` 是纯函数。它只比较 `useCellValues` 已加载的稳定格式化显示文本，绝不比较临时缩略图 URL，因此差异标记不需要额外的 SDK 调用。尚未全部加载的字段不计入差异，在「仅看差异」开启时仍保留并显示加载占位；全部取值返回后才参与过滤。`App` 只计算一次差异字段集合，并复用于统计条计数、行首标记和「仅看差异」筛选。

`CompareField.kind` 将 SDK 的字段类型归并为网格需要区分渲染的几种形态。它由 `BaseAdapter` 计算，从而使 `FieldType` 保持在 SDK 边界之内，React 层不直接依赖 SDK。

## 字段展示状态

版本 1 新增 `fieldOrderIds` 和 `wrappedFieldIds`，均默认为 `[]`。缺失或格式无效的数组回退空数组；有效数组去重并清理失效字段 ID。空字段顺序表示沿用源顺序。纯函数 `orderFields` 先排列已配置 ID，再按源顺序追加其余字段，同时用于草稿控件与已保存矩阵。新增字段默认显示、不换行，首次默认隐藏主字段的行为不变。深拷贝使两个数组在草稿和已保存配置之间隔离。旧版本忽略这些设置，再次保存可能丢弃它们；测试标签页需全部使用新版。

`App` 独立保存临时展开 ID，并按已保存的可见字段清理。`CompareTable` 合并已保存换行与临时展开状态；`FieldSelector` 只修改草稿。排序和换行不改变单元格集合，因此不会重复读取已加载的值。

## 列宽与图片浏览

列宽是即时生效并自动共享的例外，其他设置仍为草稿。共享有独立状态；失败保留本地布局并提供重试和恢复已共享列宽，放弃修改只作用于其他草稿。普通保存先等待列宽共享，失败则停止。存在待共享列宽时，刷新/数据源变更提示处理；整页离开使用浏览器的未保存警告。

版本 1 新增 `fieldColumnWidth: number | null`（默认 `null`）和 `recordColumnWidths: Record<string, number>`（默认 `{}`）。有限数值取整并限制范围，无效值和已删除记录 ID 清理；仍存在但未选中的记录保留宽度。对象键顺序不作为设置差异。旧版本保存可能丢弃新增设置，测试标签页统一使用新版。

`ConfigController` 分离已共享配置、普通草稿和待共享列宽补丁，单个 `ConfigWriteQueue` 跨数据源串行执行读写。列宽写入先读最新共享配置且只合并宽度，普通保存合并最新共享列宽；读取失败不执行过期写入。本地待共享列宽覆盖远端同列更新，其他列立即更新。不保证跨页面原子合并，同时保存仍可能覆盖。

`App` 在数据源会话内按字段/记录管理图片位置。排序、分组折叠、仅看差异及无关保存保留位置；保存隐藏/移除、附件变化、数据源变化和主动刷新清理相关位置。图片及 URL 不进入共享配置。调宽和切图不改变单元格加载 key，也不增加读取。
